# 知识模型 v0.1

## 三类知识节点

节点分为 concept、proof、exercise，分别放在 data/concepts、data/proofs、data/exercises 下，并按**知识包**组织（每包一个目录，包内按单元分层）。每包都有 package.json，列出稳定 ID 与文件位置。

`data/` 是可发布的只读课程包。教学运行时只读取其中的 Markdown、package 和 course；运行时代码位于 `src/`，AI 教师定义位于 `skills/`，可变的用户状态位于 `learners/`。知识贡献者只在课程创作阶段修改 `data/`，教学进程不得写回其中。

- concept：陈述、意义、例子和常见误区；
- proof：证明某个 concept，同一定理的不同证明分别成节点；
- exercise：声明 difficulty、tests 与 requires，供教师选题和评估。

三类节点共享全局 ID 与依赖图。理解一个定理、掌握它的一种证明、完成一道练习是三条独立进度。

概念 Markdown 的最小 frontmatter 示例：

概念 Markdown 只保留最小 frontmatter：

    ---
    id: elementary.number-theory.gcd
    title: 最大公约数
    course: course.elementary.number-theory
    status: example
    requires: ["elementary.number-theory.divisibility"]
    ---

证明节点另外声明：

    proves: elementary.number-theory.fermat-little-theorem
    method: 剩余系置换

练习节点另外声明：

    difficulty: 3
    tests: ["elementary.number-theory.chinese-remainder-theorem"]

## 两层 requires

文档级 requires 是打开整篇内容的最低标准。所有 ID 都完成后，文档才可展示。

段落级要求使用：

    <div require="elementary.algebra.linear-equation">
    这段内容只对已经完成该节点的学习者显示。
    </div>

多个 ID 使用空格或逗号分隔，并采用 AND 语义：

    <div require="concept.a concept.b">
    需要同时完成 a 和 b。
    </div>

段落标签是作者源格式。src/render.mjs 会删除不可见段落，并把可见段落的标签解包，再交给 AI 教师。

## LaTeX

只使用 Obsidian 稳定支持的分隔符：

- 行内公式：$a^2+b^2=c^2$
- 块公式：两个双美元符之间放公式

不使用旧式圆括号或方括号分隔符。

## 用户存档

learners/<id>.json 只由运行时脚本写入。主要字段：

- profile：初始化得到的目标、数学背景、证明经验、教学偏好、公式渲染和定位摘要；
- progress：任意知识节点的状态、0–6 掌握度、时间和证据；
- visits：节点被教学或回访的次数。

`src/profile.mjs` 只管理 profile，`src/progress.mjs` 只管理节点进度和访问。模型不得手工修改存档。单次会话中的“今天只听”一类覆盖保留在对话上下文中，除非学习者明确要求修改长期默认值。

## 课程

data/courses/*.md 用 frontmatter 的 nodes 数组声明课程：item（节点 ID）+ level（要求深度）+ after（课程内顺序）。课程可以选择一个包的子集，也可以跨包组合；未列入课程的前置节点由 src/path.mjs 沿 requires 自动补全（标记 auto，按 know 等级先行学习）。level 分为：

- master：灵活运用，能证明、能迁移；
- proof：理解结论与证明思路；
- know：仅知道结论。

包大纲是稳定骨架，课程是可替换的教学路线。
